# Установка и подключение RouterBox

Инструкция для ASUS RT-AX53U, OpenWrt с APK, target `ramips/mt7621` и архитектурой `mipsel_24kc`. Адрес `192.168.1.1` в командах замените своим адресом роутера, если он отличается.

## 1. Скачать сборку

Откройте [Releases](https://github.com/nekl3103/RouterBox/releases/latest) и скачайте **routerbox-mt7621-0.3.0.tar.gz**. Для обычной установки нужен этот комплект целиком.

Если используете тестовую сборку из [Actions](https://github.com/nekl3103/RouterBox/actions/workflows/build.yml), откройте успешный запуск, скачайте artifact `RouterBox-mt7621-…` и распакуйте ZIP на компьютере. Внутри будет установочный tar.gz.

## 2. Подключиться к роутеру

На компьютере выполните:

```sh
scp -O routerbox-mt7621-0.3.0.tar.gz root@192.168.1.1:/tmp/
ssh root@192.168.1.1
```

Введите пароль root. Ключ `-O` включает обычный SCP для OpenWrt, где SFTP-сервер может отсутствовать.

Убедитесь в платформе:

```sh
cat /etc/openwrt_release
apk --version
df -h /overlay /tmp
```

## 3. Распаковать комплект

Следующие команды выполняются на роутере:

```sh
cd /tmp
tar -xzf routerbox-mt7621-0.3.0.tar.gz
cd routerbox-mt7621
```

Для обычной установки сначала выполните проверку:

```sh
./install.sh --check
```

Если не хватает памяти, установщик сообщит об этом. Для установки без запуска при работающем другом VPN используйте следующий раздел: режим `--disabled` не требует памяти для немедленного запуска ядра.

## 4. Выбрать способ установки

| Команда | Результат |
| --- | --- |
| `./install.sh --flash` | Приложение и сжатое ядро на накопителе; контроллер запускается, на новой установке VPN выключен |
| `./install.sh --disabled` | Приложение и ядро без запуска и автозапуска RouterBox |
| `./install.sh --app-only` | Только приложение; URL, SHA256 и размер ядра для RAM задаются в LuCI |
| `./install.sh --check` | Только проверка, пакеты не устанавливаются |

Обычная установка:

```sh
./install.sh --flash
```

Если уже работает TrustTunnel, Passwall или другой VPN, для новой установки выполните:

```sh
./install.sh --disabled
/etc/init.d/routerbox start
```

На новой установке эта команда запускает только контроллер с выключенным VPN. Существующая сохранённая настройка включённого VPN восстанавливается при запуске службы.

Установщик добавит публичный ключ APK из комплекта и загрузит зависимости из репозиториев OpenWrt. На роутере не устанавливаются инструменты сборки.

## 5. Открыть интерфейс

В браузере откройте **http://192.168.1.1**, войдите в LuCI и перейдите в **Сервисы → RouterBox**. Если пункт не появился, обновите страницу.

На вкладке **«Подписки»** нажмите **«Добавить подписку»**, вставьте URL и укажите интервал обновления. Название и совместимые серверы загрузятся после добавления.

На вкладке **«Серверы»** проверьте список своей подписки. Неподдерживаемые записи не включаются в рабочий набор и показываются в подписке отдельно.

В окне подписки доступны фильтры названий, свой User-Agent и загрузка через работающий VPN. Результат обновления показывает добавленные, удалённые и повторяющиеся записи. Прежние выбранные серверы сохраняются с предупреждением, если они исчезли; при неудачном применении сохраняется весь прежний список.

## 6. Настроить маршрутизацию

Пример подключения YouTube, ChatGPT, Instagram, Telegram и Gemini через VPN:

1. **Маршрутизация → Добавить правило**.
2. Выберите **YouTube**, **ChatGPT / OpenAI**, **Instagram**, **Telegram**, **Gemini / Google AI**.
3. Выберите направление **VPN**.
4. Выберите режим **«Стабильный»** или **«Быстрый»**; в ручном режиме обязательно укажите конкретный сервер.
5. Отметьте серверы, которые разрешено использовать. Пустой выбор разрешает все подходящие серверы активированных подписок.
6. Добавьте правило.
7. Для **«Остального трафика»** выберите **«Напрямую»**.
8. Нажмите **«Сохранить изменения»** и дождитесь завершения.

Для собственного сайта добавьте домен, например `example.org`. Для IP — адрес или CIDR, например `203.0.113.10` или `203.0.113.0/24`. Можно выбрать направление «Напрямую», VPN или блокировку и ограничить правило устройствами.

Первое совпадение побеждает. Более конкретные исключения ставьте выше общего правила. Чтобы направлять весь внешний трафик через VPN, выберите **«Остальной трафик → Через VPN»**.

Для отдельного UDP-сервера откройте дополнительные настройки правила, включите **«Отдельный сервер для UDP»** и выберите UDP-пул. Основной пул будет обслуживать TCP. HTTPS-проверка задержки не проверяет UDP.

## 7. Проверить DNS и настройки

На вкладке **DNS** выберите резолвер и направление его запросов. По умолчанию доступны Cloudflare DoH и Quad9 DoT; стратегия предпочитает IPv4. Bootstrap DNS должен быть доступен для первоначального запуска.

В **Настройках** проверьте LAN-интерфейс (`br-lan` в обычной конфигурации) и MTU (1400 по умолчанию). Если внешний IPv6 не обрабатывается RouterBox, он блокируется для выбранных LAN.

По умолчанию при аварии ядра блокируется внешний трафик выбранных LAN. При необходимости разрешить прямой выход при отказе выберите соответствующую политику в настройках.

Во вкладке DNS можно менять порядок резолверов и настраивать общий таймаут запроса, время повторной проверки отказавшего DNS и удержания выбранного.

Сохраните изменения.

## 8. Включить VPN

Сначала остановите другой клиент, управляющий маршрутизацией этой сети. Например, для службы TrustTunnel:

```sh
/etc/init.d/trusttunnel stop
```

В RouterBox нажмите **«Включить VPN»**. Дождитесь окончания операции. Откройте **«Обзор»**: VPN должен работать, а в правиле должен отображаться выбранный сервер. При первом запуске автоматическому выбору требуется время на проверку серверов.

Откройте выбранные сайты на устройстве, подключённом к этому роутеру. Счётчики RouterBox и доступность сервера не заменяют проверку самого сайта с LAN-устройства.

Для запуска после перезагрузки:

```sh
/etc/init.d/routerbox enable
```

Если другой VPN имеет автозапуск, отключите его автозапуск отдельно, когда решите окончательно перейти на RouterBox.

## Отключение

Нажмите **«Отключить VPN»** в LuCI. Это возвращает прежние параметры DNS и снимает защитные правила.

`/etc/init.d/routerbox stop` останавливает процесс, но сохраняет защиту от утечек. Для аварийного восстановления прямого доступа:

```sh
/etc/init.d/routerbox stop
/usr/bin/routerbox cleanup
```

## Обновление

Сначала на компьютере сохраните приватную резервную копию:

```sh
ssh root@192.168.1.1 'tar -czf - /etc/routerbox /etc/config/routerbox' > routerbox-backup.tar.gz
chmod 600 routerbox-backup.tar.gz
```

Передайте новый комплект в `/tmp` и распакуйте, как в шагах 2–3. В LuCI отключите VPN, затем на роутере остановите службу и освободите RAM от распакованных файлов:

```sh
/etc/init.d/routerbox stop
rm -f /tmp/routerbox/sing-box /tmp/routerbox/core.sha
rm -f /tmp/routerbox/routerbox-controller /tmp/routerbox/controller.sha
cd /tmp/routerbox-mt7621
./install.sh --check
./install.sh --flash
```

Удалять эти файлы можно только после остановки службы. Это позволяет распаковать обновлённое ядро без хранения двух больших исполняемых файлов в RAM. Настройки и подписки сохраняются. После установки проверьте их в LuCI и включите VPN заново.

Если обновляете вариант с ядром в RAM, используйте `--app-only` и обновите URL, SHA256 и распакованный размер ядра из нового manifest.

## Очистить установочные файлы

После успешной установки:

```sh
rm -rf /tmp/routerbox-mt7621
rm -f /tmp/routerbox-mt7621-0.3.0.tar.gz
```

Рабочий каталог `/tmp/routerbox` при запущенной службе не удаляйте.

## Восстановить резервную копию

Передайте приватный архив обратно на роутер. Не используйте архив от другого роутера без проверки содержимого.

```sh
scp -O routerbox-backup.tar.gz root@192.168.1.1:/tmp/
ssh root@192.168.1.1
```

На роутере:

```sh
/etc/init.d/routerbox stop
tar -xzf /tmp/routerbox-backup.tar.gz -C /
/etc/init.d/routerbox start
```

При сохранённом включённом VPN он будет восстановлен. Для прямого выхода сначала используйте аварийное отключение из раздела выше.

## Удалить RouterBox

```sh
apk del luci-app-routerbox routerbox-core
```

DNS и собственное включение firewall восстанавливаются скриптом удаления. Настройки в `/etc/routerbox` сохраняются.

## Если что-то не работает

- Ошибка подписки DNS / TLS / таймаут: проверьте доступность ссылки с роутера и время системы; нажмите **«Обновить»**. Последний рабочий список серверов сохраняется.
- Откат применения: откройте **«Журнал»**, проверьте память и выбранные серверы; используйте актуальную сборку с исправлением 32-битных таблиц маршрутизации.
- Нет подключения: проверьте активную подписку, сервер, LAN-интерфейс и другой VPN.
- Сайт идёт напрямую: проверьте порядок правил и DNS браузера/приложения.
- После остановки нет Интернета: выполните команды аварийного восстановления.

Состояние через SSH без вывода персональных ссылок:

```sh
printf '{}' | /usr/bin/routerbox rpc call state | jsonfilter -e '@.running' -e '@.job' -e '@.events'
```
