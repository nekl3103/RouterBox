# RouterBox

[![Build RouterBox](https://github.com/nekl3103/RouterBox/actions/workflows/build.yml/badge.svg)](https://github.com/nekl3103/RouterBox/actions/workflows/build.yml)

RouterBox — клиент для OpenWrt с интерфейсом LuCI и ядром [sing-box-lx](https://github.com/Leadaxe/sing-box-lx). Он загружает подписки, проверяет совместимость серверов и направляет выбранные сайты, сервисы и устройства через VPN или напрямую.

**[Скачать сборку](https://github.com/nekl3103/RouterBox/releases/latest) · [Пошаговая инструкция](docs/INSTALL.md) · [Сборки GitHub Actions](https://github.com/nekl3103/RouterBox/actions/workflows/build.yml)**

## Поддерживаемая платформа

| Параметр | Значение |
| --- | --- |
| Проверенный роутер | ASUS RT-AX53U |
| Процессор | MediaTek MT7621 |
| OpenWrt target | `ramips/mt7621` |
| Архитектура APK | `mipsel_24kc` |
| Проверенная прошивка | OpenWrt 25.12.5, LuCI |
| Пакетный менеджер | APK |
| Приложение | 0.3.1, пакет `0.3.1-r1` |
| Ядро | `1.14.2-lx.12-router.1`, пакет `1.14.2-r13` |

Готовые пакеты предназначены для этой платформы. Старые прошивки с OPKG, другие архитектуры и другие модели этим комплектом не проверены. Должны быть доступны репозитории пакетов вашей установленной прошивки: модули ядра устанавливаются именно из них.

## Что умеет RouterBox

- Несколько подписок, обновление по расписанию, повторные попытки загрузки, свой User-Agent, загрузка напрямую или через VPN.
- Фильтры серверов по регулярным выражениям, удаление дубликатов, статистика добавленных/удалённых записей и безопасное сохранение выбора при обновлении.
- Импорт URI, Base64, sing-box JSON и совместимых записей Clash/Mihomo YAML. Неподдерживаемые записи показываются отдельно.
- Серверы по подпискам, поиск, фильтр протокола, проверка доступности и задержки.
- Выбор одного или нескольких серверов для каждого правила. Пустой выбор означает все подходящие серверы активированных подписок.
- Ручной выбор, минимальная задержка, стабильность по истории, упорядоченные резервы и распределение новых соединений.
- Маршрутизация сервисов, собственных доменов, IP/CIDR, IP и MAC устройств. Прямой выход, VPN или блокировка.
- YouTube, Instagram, Telegram, ChatGPT / OpenAI, Gemini / Google AI, Meta, Discord, TikTok, Twitter, Google Meet, HDRezka и Roblox.
- Категории [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) и списки [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains). Telegram объединяет домены двух источников и IPv4/IPv6-подсети. ChatGPT и Instagram загружаются отдельными готовыми `.srs` из [MetaCubeX/meta-rules-dat](https://github.com/MetaCubeX/meta-rules-dat), без общего архива каталога.
- Настраиваемые DNS: UDP, TCP, DoH, DoT, DoQ и HTTP/3; кеш, bootstrap, IPv4/IPv6 и выбор направления DNS-запросов.
- Обзор состояния, текущего сервера для правил, трафика, памяти, журнала и до 32 текущих соединений с устройством, маршрутом и сервером.
- Отдельный выбор пула серверов для UDP внутри VPN-правила; ограничения правил по TCP/UDP.
- Проверка конфигурации перед применением, возврат к рабочей конфигурации при ошибке, восстановление после перезапуска.

## Быстрая установка

Полная инструкция, включая настройку подписки и правил, находится в [docs/INSTALL.md](docs/INSTALL.md).

1. Скачайте `routerbox-mt7621-0.3.1.tar.gz` из [Releases](https://github.com/nekl3103/RouterBox/releases/latest).
2. Передайте архив с компьютера на роутер:

   ```sh
   scp -O routerbox-mt7621-0.3.1.tar.gz root@192.168.1.1:/tmp/
   ssh root@192.168.1.1
   ```

3. На роутере распакуйте и проверьте комплект:

   ```sh
   cd /tmp
   tar -xzf routerbox-mt7621-0.3.1.tar.gz
   cd routerbox-mt7621
   ./install.sh --check
   ```

4. Установите пакеты:

   ```sh
   ./install.sh --flash
   ```

5. Откройте `http://192.168.1.1` → **Сервисы → RouterBox**. Добавьте подписку и правило, сохраните изменения, нажмите **«Включить VPN»**.

Используйте свой адрес роутера, если он отличается. Пароль вводится в SSH вручную. Установщик проверяет платформу, контрольные суммы и свободную память. После новой установки VPN по умолчанию отключён; контроллер запускается для настройки через LuCI.

### Если уже работает TrustTunnel или другой VPN

Для новой установки без запуска RouterBox:

```sh
./install.sh --disabled
```

Этот режим устанавливает пакеты, отключает автозапуск RouterBox и не включает VPN. Режим предназначен для новой установки: уже работающий RouterBox сначала нужно остановить.

Для открытия настроек запустите контроллер:

```sh
/etc/init.d/routerbox start
```

При сохранённом `VPN включён` запуск контроллера также восстанавливает VPN. На новой установке VPN выключен. Перед включением RouterBox остановите другой клиент, который перехватывает трафик LAN. Например, если служба называется `trusttunnel`:

```sh
/etc/init.d/trusttunnel stop
```

После проверки RouterBox включите его автозапуск:

```sh
/etc/init.d/routerbox enable
```

## Как настроить подключение

### Подписки

Откройте **Подписки → Добавить подписку**. Вставьте URL, укажите период обновления и добавьте подписку. RouterBox скачает название и серверы. URL хранится и показывается обычным текстом; файлы настроек доступны root с правами 0600. Не публикуйте свои ссылки подписок.

У каждой подписки видны название, количество серверов, активация, время успешного обновления и ошибка последней попытки. **«Обновить»** загружает её заново. Неудачное обновление сохраняет предыдущие серверы. **«Активирована»** означает доступность серверов для правил, а не включённый VPN.

В окне подписки можно выбрать загрузку **«Напрямую»** или **«Через VPN»** и указать свой User-Agent. Загрузка через VPN требует работающего VPN-маршрута; прямого fallback для неё нет. Локальный прокси используется только контроллером, слушает `127.0.0.1` и защищён случайным паролем.

Фильтр **«Только совпадающие»** оставляет подходящие названия, **«Исключить совпадающие»** исключает их. Выражения задаются по одному на строке: `(?i)germany|netherlands` или `(?i)expired|test`. Число выражений ограничено 32.

При изменении параметров сервера выбор переносится только при единственном совпадении подписки, имени, адреса и протокола. Исчезнувшие выбранные записи сохраняются с предупреждением до замены пользователем. Если применение нового списка не удалось, прежние серверы и время успешного обновления сохраняются.

### Маршрутизация

Пример: через VPN только YouTube, ChatGPT, Instagram, Telegram и Gemini.

1. Откройте **Маршрутизация → Добавить правило**.
2. Выберите перечисленные сервисы.
3. Укажите направление **VPN** и режим выбора сервера.
4. Отметьте разрешённые серверы или оставьте выбор пустым для всех подходящих.
5. Добавьте правило; для **«Остального трафика»** выберите **«Напрямую»**.
6. Нажмите **«Сохранить изменения»**, затем **«Включить VPN»**.

Свои домены задавайте без схемы и пути: `example.org`. IP задавайте как адрес или подсеть: `203.0.113.10`, `203.0.113.0/24`. В окне правила можно ограничить его конкретными LAN-устройствами.

Правила выполняются сверху вниз, первое совпадение определяет маршрут. Категории, сайты и IP назначения внутри правила объединяются через OR; ограничения устройств добавляются через AND. Стрелки ↑/↓ меняют порядок. Чтобы весь внешний трафик шёл через VPN, выберите **«Остальной трафик → Через VPN»** и настройте его серверы.

В дополнительных настройках правила можно выбрать **TCP**, **UDP** или оба протокола. Переключатель **«Отдельный сервер для UDP»** добавляет UDP-пул с собственным режимом и выбором сервера; основной пул обслуживает TCP. Проверки доступности остаются HTTPS-проверками: они не доказывают прохождение UDP или работу звонков.

### Как выбирается сервер

| Режим | Поведение |
| --- | --- |
| Ручной | Используется указанный сервер |
| Быстрый | Приложение выбирает сервер с меньшей задержкой |
| Стабильный | Учитываются успешность проверок, колебания и средняя задержка |
| Резервирование | Серверы проверяются в заданном порядке |
| Распределение | Новые соединения распределяются по пулу серверов |

Оценка стабильности требует накопленной истории. Проверки используют HTTPS, интервал 300 секунд, окно 30 измерений и защиту от частых переключений. Это не измерение скорости скачивания. Распределение не складывает скорости серверов для одного соединения. На вкладке **«Серверы»** ручная проверка доступна при работающем VPN для серверов, включённых в сохранённые правила.

### DNS

На вкладке **DNS** доступны готовые Cloudflare, Google, Quad9 и AdGuard, а также собственный адрес. Примеры: `https://1.1.1.1/dns-query`, `tls://9.9.9.9`, `udp://1.1.1.1`.

Укажите режим выбора DNS, стратегию IP и направление **«Напрямую»** или **«Через VPN»**. Bootstrap DNS нужен для первоначального разрешения имён DNS-серверов и VPN-серверов. Отдельный резолвер можно выбрать внутри доменного правила. DNS по отдельным устройствам через общий dnsmasq не поддерживается.

Порядок DNS задаёт начальный приоритет стабильного режима. Кнопки ↑/↓ меняют порядок. Таймаут общего запроса настраивается в пределах 2–30 секунд; отдельно задаётся время повторной проверки отказавшего DNS и удержания выбранного.

Локальные имена обслуживает dnsmasq. После отключения RouterBox восстанавливает прежние upstream DNS. Встроенный DoH в браузере или приложении может обходить DNS роутера и мешать доменным правилам.

### Настройки и поведение при отказе

Обычно LAN-интерфейс — `br-lan`, MTU — 1400. Меняйте их в соответствии со своей сетью. При выключенной обработке IPv6 внешний IPv6 выбранных LAN блокируется, чтобы не обходить IPv4-правила; локальные IPv6-адреса остаются доступны.

По умолчанию при аварии ядра блокируется весь внешний трафик выбранных LAN, включая направления «Напрямую». Локальная сеть и управление роутером сохраняются. Альтернативная политика в настройках разрешает прямой выход при отказе.

**Обычная остановка init-службы сохраняет защитные правила.** Для штатного отключения используйте **«Отключить VPN»** в LuCI. Для аварийного восстановления прямого подключения:

```sh
/etc/init.d/routerbox stop
/usr/bin/routerbox cleanup
```

## Место на роутере

В проверенной сборке ядро занимает около **13,8 МиБ**, контроллер около **2,9 МиБ** в сжатом виде. Основные зависимости устанавливаются через APK отдельно. Точные размеры и SHA256 находятся в `manifest.json`.

Исполняемые файлы распаковываются в `/tmp/routerbox`: ядро около 46,8 МиБ, плюс контроллер и память работающих процессов. Свободное место во flash не заменяет оперативную память. Установщик проверяет оба ограничения и останавливается при недостатке ресурса.

На роутере не нужны Go, Git, Docker, Python, Node.js или SDK. История, каталог и журнал находятся в RAM. В постоянной памяти сохраняются настройки, серверы, резерв DNS и только выбранные бинарные `.srs` списки. Невыбранные списки удаляются после успешного применения.

Лимиты: 1024 импортированных сервера, 64 активных сервера, 32 внутренних селектора, 120 измерений на сервер, 100 событий и 8 МиБ выбранных правил. Для WireGuard/AmneziaWG/MASQUE допускается не более двух активных туннелей суммарно.

После установки удалите установочные файлы:

```sh
rm -rf /tmp/routerbox-mt7621
rm -f /tmp/routerbox-mt7621-0.3.1.tar.gz
```

Не удаляйте `/tmp/routerbox` при работающей службе.

### Загрузка ядра в RAM

Для установки приложения без ядра во flash:

```sh
./install.sh --app-only
```

В **Настройки → Хранение ядра** выберите **«Загрузка ядра в RAM»**. Укажите HTTPS URL `sing-box-1.14.2-lx.12-mt7621.gz`, SHA256 сжатого архива и `size` распакованного файла из `manifest.json`. В Releases этот gzip опубликован отдельно.

Ссылка должна быть доступна после каждой перезагрузки до запуска туннеля. Формат — gzip одного исполняемого файла, не tar.gz установочного комплекта. Если ранее установлен `routerbox-core`, переключение режима не удаляет его; после проверки RAM-варианта его можно удалить командой `apk del routerbox-core`.

## Обновление, резервная копия и удаление

Полный порядок обновления и восстановления — в [инструкции](docs/INSTALL.md#обновление).

Настройки содержат ссылки и параметры серверов. Резервную копию храните приватно. С компьютера:

```sh
ssh root@192.168.1.1 'tar -czf - /etc/routerbox /etc/config/routerbox' > routerbox-backup.tar.gz
chmod 600 routerbox-backup.tar.gz
```

Удаление пакетов:

```sh
apk del luci-app-routerbox routerbox-core
```

Скрипт удаления останавливает службу, восстанавливает принадлежащие RouterBox настройки DNS и удаляет собственное включение firewall. Каталог настроек `/etc/routerbox` сохраняется.

## Сборка на компьютере

Нужны Git, Go, Python 3, OpenSSL и запущенный Docker. Linux/macOS, архитектура компьютера AMD64 или ARM64. Go автоматически использует закреплённый toolchain `1.26.8`.

```sh
git clone https://github.com/nekl3103/RouterBox.git
cd RouterBox
./scripts/build.sh
```

Результат в `dist/`:

| Файл | Назначение |
| --- | --- |
| `routerbox-mt7621-0.3.1.tar.gz` | Установочный комплект с инструкцией, пакетами и ключом |
| `luci-app-routerbox-0.3.1-r1.apk` | Контроллер и LuCI |
| `routerbox-core-1.14.2-r13.apk` | Сжатое ядро |
| `sing-box-1.14.2-lx.12-mt7621.gz` | Архив для загрузки ядра в RAM |
| `manifest.json` | Версия, размеры, исходный commit и SHA256 ядра |
| `SHA256SUMS` | Контрольные суммы содержимого установочного комплекта |
| `keys/routerbox.pub` | Публичный ключ APK |

Ядро закреплено на commit `a97658c1d122a64b405621a94e1db971f8939f8d` (`v1.14.2-lx.12`). Сборка применяет `patches/sing-tun-32bit-route-table.patch`: случайный номер таблицы маршрутизации остаётся положительным на 32-битном MT7621. Исправленное ядро обозначено `1.14.2-lx.12-router.1`.

Теги: `with_gvisor,with_quic,with_wireguard,with_utls,with_clash_api,with_xhttp,with_awg`. Доступны VLESS/REALITY/XHTTP, VMess, Trojan, Shadowsocks, Hysteria/Hysteria2, TUIC, AnyTLS, WireGuard/AmneziaWG и другие протоколы этой сборки. Tailscale, OpenVPN, OpenConnect и Naive исключены для уменьшения размера. Каждая импортированная запись проверяется ядром.

APK подписываются RSA-ключом `build/routerbox-private.pem`; при отсутствии он генерируется. Закрытый ключ не входит в Git или установочный комплект. Публичный ключ включён в комплект, установщик добавляет его в `/etc/apk/keys`. `--allow-untrusted` не требуется. Для стабильной подписи сохраняйте приватный ключ между сборками.

### Проверки

```sh
go test -race ./...
go vet ./...
node --check files/www/luci-static/resources/view/routerbox/main.js
node tests/ui-smoke.cjs
./scripts/test-linux.sh
```

`test-linux.sh` запускается после `build.sh`, собирает Linux-ядро для архитектуры компьютера и проверяет конфигурацию и переключение серверов в Docker. Для дополнительной проверки внешних списков:

```sh
ROUTERBOX_TEST_SERVICES=1 ./scripts/test-linux.sh
```

Проверки доступа к реальным подпискам не запускаются в CI. Источники, ключи и персональные настройки в `build/`, `dist/`, `output/` и `.playwright-cli/` исключены из Git.

## Сборка в GitHub Actions

Workflow [Build RouterBox](.github/workflows/build.yml) запускается при push в `main`, pull request, создании тега `v*` и вручную через **Actions → Build RouterBox → Run workflow**.

Он проверяет Go и LuCI, собирает MIPS little-endian soft-float пакеты, проверяет их подписи, запускает тесты с Linux-ядром, проверяет контрольные суммы и сохраняет установочный комплект в **Artifacts**. Для скачивания artifact откройте завершённый запуск Actions и скачайте `RouterBox-mt7621-…`; распакуйте ZIP на компьютере и передайте tar.gz на роутер.

Тег `v*` дополнительно публикует файлы в **Releases**, откуда их можно скачать непосредственно. Для нового выпуска сначала обновите версии пакетов в скриптах, затем:

```sh
git add .
git commit -m "Prepare RouterBox release"
git push origin main
git tag v0.3.1
git push origin v0.3.1
```

Имя тега не меняет внутренние версии приложения и APK автоматически.

Для постоянной подписи добавьте в **Settings → Secrets and variables → Actions → New repository secret** секрет `ROUTERBOX_APK_SIGNING_KEY` с полным содержимым вашего RSA PEM-ключа. Без секрета каждый запуск генерирует отдельный ключ; его публичная часть входит в соответствующий комплект. Pull request не получает этот секрет. Workflow не публикует приватный ключ и конфигурацию подписок.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Нет пункта RouterBox | Вход root в LuCI; обновите страницу после установки |
| Ошибка DNS / TLS / таймаут загрузки | Доступность подписки с роутера, DNS и время системы; нажмите «Обновить». Старые серверы сохраняются |
| «Применение не удалось» | Журнал RouterBox, RAM, поддерживаемые серверы. Предыдущая рабочая конфигурация восстанавливается |
| После включения нет Интернета | Активную подписку, доступный сервер, LAN-интерфейс и отсутствие другого перехватывающего VPN |
| Сайт идёт напрямую | Порядок правил, домены/CDN сайта, DNS браузера и выбранные категории |
| После остановки нет Интернета | Используйте «Отключить VPN» или команды аварийного восстановления выше |
| Ошибка установки модуля ядра | Репозитории APK должны соответствовать установленной прошивке |

Журнал доступен во вкладке **«Журнал»**. Проверка состояния из SSH без вывода ссылок подписок:

```sh
printf '{}' | /usr/bin/routerbox rpc call state | jsonfilter -e '@.running' -e '@.job' -e '@.events'
```

Диагностика запуска ядра хранится в `/tmp/routerbox/core-error.log` с доступом только root. Проверяйте время файла: он может относиться к предыдущей ошибке. Перед публикацией журналов удаляйте персональные данные.
